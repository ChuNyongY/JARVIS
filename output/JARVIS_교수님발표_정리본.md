# JARVIS-PC 교수님 발표 정리본

## 30초 소개

JARVIS-PC는 사용자의 음성 명령을 받아 Windows 작업을 수행하는 에이전트입니다. 핵심은 PC를 클릭하는
기능 자체가 아니라, 사용자의 말을 실제 명령으로 볼지, 그 행동을 자동 실행해도 되는지, 실행 결과가
정말 맞는지를 서로 다른 모듈이 판단하도록 만든 것입니다. 언어 모델은 계획만 제안하고, 실제 권한은
등록된 기능, 위험 정책, 사용자 승인, 독립 검증기가 통제합니다.

## 정확히 무엇을 만들고 있는가

전체 처리 순서는 다음과 같습니다.

1. 호출어, 음성 구간, 음성 인식으로 사용자의 말을 받습니다.
2. 로컬 의도 판별기가 명령, 대화, 질문, 인용, 불확실, 중단을 구분합니다.
3. 현재 앱과 로컬 기억 중 필요한 정보만 언어 모델에 제공합니다.
4. NVIDIA NIM의 언어 모델이 허용된 기능만 사용한 구조화된 JSON 계획을 제안합니다.
5. 정책 엔진이 대상, 인자, 위험도, 현재 문맥을 다시 검사합니다.
6. 위험 행동은 정확한 행동에 묶인 승인이나 Windows Hello 인증을 요구합니다.
7. Windows 실행기가 허용된 기능만 실행합니다.
8. 독립 검증기가 파일, 프로세스, 창, 음량 등 실제 운영체제 상태를 다시 확인합니다.
9. 실패하면 안전한 범위에서만 재시도하거나 재계획하고, 모든 결과를 비밀 제거 감사 로그에 남깁니다.

현재 제품 조립에는 시스템 정보, 파일 목록, 등록 앱 실행, Explorer, Windows 설정, 음량, 저장공간,
파일 이동과 휴지통, 제한된 브라우저 탐색, 로컬 기억 검색 등을 포함한 13개 기능이 연결돼 있습니다.

## 왜 필요한가

언어 모델은 문장을 잘 만들지만 다음 문제를 스스로 보장하지 못합니다.

- 음성을 정확히 받아써도 단순 대화인지 실제 명령인지 알 수 없습니다.
- 화면이 바뀌면 클릭 대상이 달라질 수 있습니다.
- 웹페이지나 문서 안의 공격 문장을 사용자 명령으로 오해할 수 있습니다.
- 실행기가 성공이라고 보고해도 실제 파일이나 창 상태가 다를 수 있습니다.
- 삭제, 설치, 외부 전송은 작은 오류도 큰 피해가 됩니다.

따라서 모델에게 모든 권한을 주지 않고, 계획 제안과 실행 권한, 완료 판정을 분리해야 합니다.

## 하네스, 스킬, 도구, 기능의 차이

- **하네스(Harness)**: 모델 호출, 문맥, 도구 선택, 정책, 승인, 오류 처리, 검증을 연결한 전체 실행 틀입니다.
- **스킬(Skill)**: 자주 하는 작업을 어떤 순서로 처리할지 적은 재사용 절차입니다.
- **도구(Tool)**: 파일 읽기나 음량 변경처럼 실제 상태를 읽거나 바꾸는 한 번의 동작입니다.
- **기능(Capability)**: 허용된 인자, 대상, 위험도가 명시된 실행 계약입니다.

스킬은 실행 권한이 아닙니다. 스킬이 작업 순서를 알려 주더라도 실제 권한은 등록된 기능과 정책, 승인,
검증이 결정합니다.

## 논문에서 무엇을 연구하는가

연구 질문은 다음과 같습니다.

> 같은 언어 모델과 같은 Windows 작업에서 의도 판별, 위험 정책, 사용자 승인, 독립 검증, 제한적 복구를
> 추가하면 작업 성공률, 위험 실행, 사용자 확인 부담, 시간과 비용이 어떻게 달라지는가?

특정 NIM 모델이 우수하다는 논문이 아닙니다. 모델은 교체 가능한 계획 생성 부품이며 연구 기여는 실행
하네스입니다.

## 어떤 실험을 하는가

같은 모델, 같은 작업, 같은 초기 상태에서 하네스만 바꾼 네 조건을 비교합니다.

| 조건 | 구성 | 확인하려는 내용 |
|---|---|---|
| B0 | 직접 한 번 실행 | 기본 성공률과 위험 기준선 |
| B1 | 모든 부작용을 사용자에게 확인 | 단순 확인 방식의 안전성과 확인 부담 |
| P1 | 의도 판별과 위험 정책 | 오실행과 불필요한 확인 감소 |
| P2 | P1에 독립 검증과 제한된 복구 추가 | 거짓 성공 감소와 복구율 변화 |

주 지표는 독립 검증기가 판정한 작업 성공률, 의도하지 않은 실행률, 위험 실행률, 사용자 확인 횟수입니다.
복구율, 검증 정확도, 단계별 지연시간, 모델 호출 수와 토큰도 함께 측정합니다.

## 기존 AI 에이전트와 무엇이 다른가

Claude Computer Use, Open Interpreter, Microsoft UFO2 같은 시스템도 실제 PC 조작과 다단계 작업을
지원합니다. 따라서 PC를 조작한다는 사실만으로는 차별화가 되지 않습니다.

JARVIS-PC의 연구 초점은 다음과 같습니다.

1. 상시 음성 환경에서 명령과 대화, 인용, 불확실 발화를 실행 전에 구분합니다.
2. 언어 모델의 계획 제안과 실제 실행 권한을 분리합니다.
3. 위험도에 따라 자동 실행, 승인, 강한 인증을 구분합니다.
4. 실행기의 성공 보고를 믿지 않고 실제 운영체제 상태를 독립적으로 확인합니다.
5. 동일 작업을 B0/B1/P1/P2 exact grid로 비교합니다.

## 선례와 관련 논문

- **ReAct**: 추론과 행동을 번갈아 수행하고 새 관찰로 계획을 갱신합니다.  
  https://arxiv.org/abs/2210.03629
- **Voyager**: 성공한 절차를 스킬 라이브러리로 저장하고 재사용합니다.  
  https://arxiv.org/abs/2305.16291
- **SWE-agent**: 에이전트가 사용하는 컴퓨터 인터페이스 설계가 실제 성능과 행동에 영향을 줍니다.  
  https://arxiv.org/abs/2405.15793
- **OSWorld**: 실제 운영체제 앱과 실행 후 상태를 이용해 컴퓨터 사용 에이전트를 평가합니다.  
  https://arxiv.org/abs/2404.07972
- **Windows Agent Arena**: 재현 가능한 Windows 작업과 병렬 평가 환경을 제공합니다.  
  https://arxiv.org/abs/2409.08264
- **OS-Harm**: 사용자 오용, 프롬프트 주입, 모델 오작동을 분리해 컴퓨터 사용 에이전트의 안전을 평가합니다.  
  https://arxiv.org/abs/2506.14866
- **OSWorld 2.0**: 긴 실제 작업에서 제약 기억, 중간 정보 반영, 질문, 결과 검증이 여전히 어렵다고 보고합니다.  
  https://arxiv.org/abs/2606.29537
- **AI Agents That Matter**: 정확도뿐 아니라 비용과 재현성을 함께 평가해야 한다고 지적합니다.  
  https://arxiv.org/abs/2407.01502

## 기존 에이전트보다 얼마나 효율적인가

현재 단계에서는 몇 퍼센트 더 효율적이라고 주장하면 안 됩니다. 전체 120개 실험 셀 중 현재 PC에서
가능한 70개를 수집했고, snapshot VM이 필요한 50개가 남아 있습니다.

효율성은 다음과 같이 계산할 예정입니다.

> 검증된 작업 성공 ÷ 시간, 모델 호출, 토큰, 사용자 확인 부담

P2는 오실행과 거짓 성공을 줄이고 일부 실패를 복구할 가능성이 있지만, 추가 관찰과 검증 때문에 시간이
늘 수 있습니다. 완전한 paired 실험 뒤 성공률과 비용을 함께 비교해야 합니다.

## 현재 진행 현황

| 단계 | 상태 | 교수님께 설명할 근거 |
|---|---|---|
| 안전 제어 핵심 | 완료 | 형식화된 계획, 정책 검사, 사용자 승인, 실행 후 검증, STOP, 감사 기록이 연결되어 있습니다. |
| Windows 제품 조립 | 완료 | 13개 기능이 생성되며 자격 증명 관리자, 문맥·기억, 서비스 경로가 연결되어 있습니다. |
| 자동 시험·배포 산출물 | 완료(서명 제외) | 회귀 시험 766개 통과, 3개 건너뜀, 줄 기준 시험 범위 83%입니다. 설치 프로그램으로 실제 최초 설치를 완료했고 원본과 설치본 파일 목록(manifest)이 일치했습니다. 다만 신뢰할 수 있는 코드 서명(Authenticode) 인증서는 아직 없습니다. |
| 벤치마크 수집 | 진행 중 | 전체 120칸 중 70칸(58.3%)을 완료했습니다. 현재 PC에서 가능한 70칸은 모두 끝났고 매 시험마다 초기 상태로 되돌릴 수 있는 가상머신(snapshot VM)이 필요한 50칸이 남았습니다. |
| 실장비·사용자 연구 | 대기 | 마이크·스피커·윈도우 헬로(생체정보 또는 PIN 인증) 및 참가자 연구는 새 동의와 외부 실험 조건이 필요합니다. |

따라서 “프로그램을 아직 못 만들었다”가 아니라, **핵심 프로그램은 동작하고 자동 검증까지 끝났으며 논문의 비교 결론을 확정할 외부 실험 증거를 채우는 단계**라고 설명하는 것이 정확합니다.

## 현재 구현 증거와 남은 항목

확인된 기준은 전체 회귀 766 통과, 3 건너뜀, 코드 줄 기준 시험 범위 83%, 시스템 점검 15/15 통과,
13개 기능 제품 서비스 조립 성공, 설치 프로그램 실제 최초 설치와 파일 목록(manifest) 일치, 벤치마크 70/120 셀 수집입니다.

남은 외부 증거는 초기화 가능한 가상머신(snapshot VM) 50칸, 코드 서명 인증서, 실제 음성·윈도우 헬로(생체정보 또는 PIN 인증) 검증, 참가자 연구입니다.
따라서 현재 결과물은 강한 안전 제어 시제품이며 논문 결론은 남은 실험 뒤 확정합니다.

## 자주 받을 질문에 대한 짧은 답

### 왜 NIM을 사용했는가?

한국어 이해와 구조화된 계획 생성을 위한 부품으로 사용합니다. 모델은 교체할 수 있으며 논문의 핵심은
NIM 자체가 아니라 모델의 계획을 안전하게 실행하는 하네스입니다.

### 완전 자율 시스템인가?

아닙니다. 허용된 기능만 실행하고 위험 행동은 사용자 승인이나 강한 인증을 요구하는 제한된 자율
시스템입니다.

### 스킬이 있으면 마음대로 실행할 수 있는가?

아닙니다. 스킬은 절차만 제공합니다. 실행 권한은 등록 기능, 정책, 승인, 검증이 통제합니다.

### 왜 모든 것을 사용자에게 물어보지 않는가?

모든 행동을 확인하면 사용자가 확인에 익숙해져 무심코 승인할 수 있고 작업 부담도 커집니다. 따라서 낮은
위험은 자동화하고 위험 행동만 정확한 대상과 함께 승인받는 방식을 비교합니다.

### 한 문장 결론

> JARVIS-PC는 언어 모델이 Windows 행동을 제안하되, 실제 권한과 완료 판정은 검증 가능한 하네스가
> 담당하도록 만든 음성 기반 PC 작업 에이전트입니다.
