# JARVIS-PC 참가자 비교실험 운영안

이 문서는 B0/B1/P1/P2 비교실험의 운영 절차다. 실제 모집·녹음·장치 사용 전에 지도교수와 학교의
연구윤리 절차 적용 여부를 확인하고, 참가자의 자발적 동의를 별도로 받아야 한다.

## 연구 질문

같은 언어 모델과 같은 작업에서 실행 하네스의 제어 수준만 바꿨을 때 다음 값이 어떻게 달라지는지
측정한다.

- 의도하지 않은 실행률(UER)
- 승인 없이 수행된 고위험 실행률
- 의도된 작업 성공률(TSR)
- 사용자 확인 횟수
- 전체 지연시간

## 조건

- B0: 하네스가 없는 직접 실행 기준선
- B1: 모든 행동을 확인하는 기준선
- P1: 의도 판별과 위험 정책 적용
- P2: P1에 실행 후 독립 검증과 제한된 복구를 추가

조건마다 같은 모델, 작업, 입력, 평가기와 초기 상태를 사용한다. 위험하거나 비가역적인 작업은 실제
사용자 PC에서 실행하지 않고 snapshot 복원이 검증된 VM에서만 수행한다.

## 참가자 식별과 개인정보

- 이름·학번·이메일 대신 무작위 `participant_id`를 사용한다.
- 분석 파일에는 발화 원문, 음성, 화면, 파일 경로, 계정 정보를 넣지 않는다.
- 원본 음성이 필요한 별도 음성 정확도 연구는 이 실험과 분리하고 별도 동의·보관·폐기 기간을 정한다.
- 참가자는 이유를 밝히지 않고 언제든 중단할 수 있다.

## 동의 확인

실험 시작 전에 다음 내용을 쉬운 말로 설명하고 서면 또는 학교가 승인한 방식으로 동의를 기록한다.

1. 연구 목적과 예상 소요 시간
2. 수행할 PC 작업과 위험 작업의 VM 격리
3. 수집하는 값과 수집하지 않는 값
4. 중단 방법과 불이익 없는 철회
5. 자료 보관 기간, 접근 권한, 폐기 방법
6. 문의 담당자와 이상 상황 보고 방법

마이크·스피커·Windows Hello는 각각 사용 직전에 다시 동의를 받는다. 한 장치에 대한 동의를 다른
장치나 이후 세션에 재사용하지 않는다.

## 실험 순서

1. 동의와 참가 가능 조건을 확인한다.
2. 개인 식별정보와 분리된 무작위 participant ID를 발급한다.
3. 연습용 작업으로 STOP과 승인 화면 사용법을 설명한다. 연습 결과는 분석에 넣지 않는다.
4. 조건 순서는 참가자마다 균형화해 학습·피로 효과를 줄인다.
5. 각 scenario를 동일한 초기 상태에서 실행한다.
6. 각 조건마다 `executed`, `approval_obtained`, `task_success`, `confirmations`,
   `total_latency_ms`만 기록한다.
7. 오류·불편·중단 요청이 있으면 즉시 실행을 멈추고 원인을 자유서술로 분석 파일에 넣지 않는다.
8. 세션 종료 후 참가자에게 저장된 항목과 철회 방법을 다시 안내한다.

## 데이터 품질 검사

각 participant/scenario 묶음에는 B0, B1, P1, P2가 정확히 한 번씩 있어야 한다. 네 조건의
`intended_command`와 `ground_truth_risk`가 일치하지 않거나 조건이 누락·중복되면 전체 입력을
분석하지 않는다.

```powershell
.\.venv\Scripts\python.exe -m javis_core.cli analyze-study `
  C:\absolute\study_observations.json
```

분석 보고서에 participant ID는 출력되지 않는다. p-value만으로 우월성을 선언하지 않고 효과 크기,
Wilson 95% 구간, 확인 부담, 지연시간, 표본 구성과 순서 효과를 함께 보고한다.

## 중단 기준

- 참가자가 중단을 요청함
- STOP이 동작하지 않음
- 승인하지 않은 고위험 행동이 시도됨
- snapshot 복원 또는 evidence 서명이 실패함
- 개인정보나 비밀값이 예상하지 않은 위치에 기록됨
- 연구자가 동일 초기 상태를 보장할 수 없음

중단된 실행을 성공이나 실패 관찰값으로 임의 변환하지 않는다. 원인을 해결하고 새 동의를 받은 별도
세션에서만 다시 수행한다.
