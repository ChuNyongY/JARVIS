# 한국어 호출어 모델 실험계획서

이 문서는 `헤이 자비스` 호출어 모델을 만들고 비교할 때, 같은 음성에 맞춘 결과를 성능처럼
보고하지 않기 위한 사전 절차다. 실제 녹음 전 지도교수와 학교의 연구윤리 절차 적용 여부를 확인하고,
원음 수집·보관·폐기에 대한 별도 동의를 받아야 한다.

## 무엇을 비교하는가

- B0: 현재 공식 영어 `hey_jarvis_v0.1` 모델
- B1: 고정 SHA-256의 공개 RepCNN 후보
- P1: 별도 학습 자료로 만든 한국어 `헤이 자비스` 후보

세 모델은 같은 최종 시험 WAV, 같은 16 kHz mono 변환, 사전에 고정한 모델별 임계값으로 비교한다.
공개 후보의 이름이나 무음 연결 시험 결과는 한국어 성능 근거가 아니다. P1이 기준을 통과하기 전에는
제품 기본 모델을 바꾸지 않는다.

연구 질문은 다음과 같다.

1. P1의 오거부율(FRR)이 B0·B1보다 낮은가?
2. FRR을 낮추면서 오수락률(FAR)이 사전 기준을 넘지 않는가?
3. 거리와 소음이 바뀌어도 그 차이가 유지되는가?
4. 한 세션에 맞춘 결과가 다른 날의 최종 시험에서도 재현되는가?

## 자료를 반드시 나누는 이유

자료는 사람과 녹음 세션을 기준으로 세 묶음으로 분리한다.

- 학습 묶음: P1의 가중치를 만드는 데만 사용
- 보정 묶음: 각 모델의 임계값을 한 번 고정하는 데만 사용
- 최종 시험 묶음: 모든 모델과 임계값이 잠긴 뒤 한 번 평가

최종 시험 결과를 본 뒤 모델, 전처리, 임계값을 바꾸면 그 결과는 더 이상 최종 시험이 아니다. 바꾼
모델은 새 버전과 새 SHA-256을 부여하고, 한 번도 사용하지 않은 새 최종 시험 묶음으로 평가한다.
개인화 모델은 같은 사람의 다른 날 세션을 나누고, 일반화 모델은 같은 사람의 음성이 서로 다른
묶음에 섞이지 않도록 참가자 단위로 나눈다.

## 녹음 조건

자료 형식 1.1의 조건을 사용한다.

- 거리: 0.5 m, 1~2 m, 3~5 m
- 소음: 조용함, 사람 말소리, 생활 소음
- 세션: 서로 다른 날 또는 충분한 휴식 뒤 다시 시작한 회차
- 표본 종류: 호출어 포함과 비호출어

예비실험은 각 거리×소음×표본 종류에서 3회 이상 녹음한다. 이 값은 장치·절차 오류를 찾기 위한
것이며 논문 성능 결론에 쓰지 않는다. 본실험은 각 셀 5회 이상을 시작점으로 삼되, 최종 참가자 수와
표본 수는 지도교수와 통계적 검정력 검토 뒤 사전 고정한다.

비호출어는 한 종류만 반복하지 않는다. 미리 정한 목록에서 무음·주변 소리, 일반 한국어 명령,
발음이 비슷하지만 정확한 호출어는 아닌 문장을 균형 있게 사용한다. 정확한 `헤이 자비스`가 들어간
음성은 반드시 호출어 포함으로 표시한다. 녹음 중 실수한 표본을 조용히 다시 분류하지 않고 제외 코드와
재녹음 사실을 실험 일지에 남긴다.

소음 이름만 기록하고 실제 음압을 측정하지 않았다면 “조용함/말소리/생활 소음 조건”이라고만 쓴다.
dB(A)나 신호 대 잡음비(SNR)를 주장하려면 같은 위치에서 교정된 측정 방법과 값을 별도 기록한다.

## 수집 절차

1. 모델과 독립된 수집 계획의 순서를 고정하고 계획 파일의 SHA-256을 기록한다.
2. 참가자에게 목적, 원음 보관 위치·기간, 철회 방법과 예상 시간을 설명한다.
3. 매 세션 새 `동의 <무작위 토큰>`을 입력한 뒤, 각 표본 직전 `준비`를 입력한다.
4. 화면 안내에 맞춰 한 표본만 녹음한다. 장치 오류나 중단 시 전체 미완성 폴더를 폐기하고 새 세션으로
   시작한다.
5. 생성된 manifest의 파일 SHA-256과 사용자 전용 Windows 접근 권한을 확인한다.
6. 원음과 동의 기록은 분석 보고서와 분리하고, 승인된 연구자만 접근한다.

예비 계획 실행 예시는 다음과 같다. 명령만 표시하는 것으로는 마이크가 열리지 않으며, 대화형 동의와
표본별 준비 확인이 모두 필요하다.

```powershell
python -m javis_core.cli capture-wakeword-corpus `
  .\evaluation\wakeword_capture_plan.example.json `
  C:\absolute\new-wake-corpus-directory
```

## 임계값 고정과 최종 평가

보정 묶음에서 모델별 임계값 후보를 미리 정한 동일한 격자로 비교한다. FAR 상한을 먼저 만족하는
후보 중 FRR이 가장 낮은 값을 선택하고, 동률 처리 규칙까지 결과를 보기 전에 기록한다. 본 프로젝트의
보정 명령은 0.50~0.99를 0.01 간격으로 계산하고 FRR 최소, FAR 최소, 더 높은 임계값 순서로
결정한다. 가능한 후보가 없으면 실패로 닫힌다. 최종 시험에서는 선택된 임계값을 바꾸지 않는다.

최종 보고에는 다음을 함께 제시한다.

- 전체 TP, TN, FP, FN, 추론 실패 수, FAR, FRR
- 거리·소음·세션 조합별 같은 값
- 각 비율의 분자와 분모 및 95% 신뢰구간
- 모델 파일 SHA-256, 자료 manifest SHA-256, 임계값, 실행 환경
- 제외·중단된 표본 수와 사전에 정한 이유

추론 실패는 제거하지 않는다. 호출어 표본의 실패는 FN, 비호출어 표본의 실패는 FP다. 표본 수가
작을 때 0%는 오류 가능성이 0이라는 뜻이 아니므로 분자·분모와 Wilson 95% 구간을 함께 해석한다.
조건별 결과가 나쁘면 전체 평균 하나로 숨기지 않는다.

## 제품 채택 기준

정확한 수치 기준은 본실험 전에 지도교수와 고정한다. 최소한 다음을 모두 만족해야 한다.

- 최종 시험에서 미리 정한 FAR 상한 통과
- 전체 FRR 목표 통과
- 어느 필수 거리·소음 조건도 별도 실패 한도를 넘지 않음
- 추론 실패율과 CPU 지연시간 한도 통과
- 모델 라이선스와 학습 자료 사용 조건 확인

하나라도 실패하면 P1은 실험 후보로 남고 제품 기본 호출어 모델로 승격하지 않는다. 기준을 바꿀
필요가 생기면 변경 이유와 시점을 기록하고 새 최종 시험 자료로 다시 평가한다.

## 중단·폐기 기준

- 참가자가 중단 또는 철회를 요청함
- 동의 없이 마이크가 열리거나 원음이 예상 밖 위치에 생성됨
- 원음 파일 ACL 또는 SHA-256 검증 실패
- 조건·정답 label이 모호함
- 학습·보정·최종 시험 자료가 섞임
- API key, 계정 정보, 장치명 또는 사람 식별정보가 manifest/report에 들어감

중단된 표본을 임의로 성공·실패로 바꾸지 않는다. 원음 폐기 요청은 동의서의 절차에 따라 처리하고,
이미 공개된 집계 자료에서 개인을 복원할 수 없도록 처음부터 보고 항목을 최소화한다.
